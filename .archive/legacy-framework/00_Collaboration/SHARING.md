# 共享边界

私有仓库也会把上传内容提供给有权限的成员。加入仓库的聊天、个人技能和本机环境不会自动同步。

## 当前规则

- `.gitignore` 继续忽略题目、参考资料、数据、结果、论文和笔记六个目录的内容，仅允许各目录的空白 `.gitkeep` 占位文件，以便队友获得目录结构。
- `04_Code` 和本协作目录可以被 Git 识别，但“可被识别”不表示“获准上传”。每次提交仍需检查内容。
- 此次模板只有通用说明和空白字段；未来填入真实团队内容后，提交及上传前应重新审查并获得用户确认。
- 密钥、密码、虚拟环境与缓存不提交。忽略规则不会取消已跟踪文件的跟踪，也不能撤回历史泄露。

## 两种资料交接方式

1. 经用户明确确认后，将指定的非敏感材料纳入仓库。仅为获准文件调整忽略规则，不对整个数据或论文目录解除限制。
2. 对受限制或体积较大的材料，使用团队认可的其他共享位置。在交接文件中写清访问方法、文件版本和校验值；不填写密码、私密令牌或带访问密钥的链接。

涉及真实数据时先选定共享方式。不能因为代码已上传，就假定队友也拿到了运行所需的数据。

## 提交与上传检查

1. 逐个检查新增和修改文件，确认是否包含真实数据、团队资料或个人信息。
2. 只暂存具体文件路径，运行 `git diff --cached --stat` 和 `git diff --cached` 检查内容。
3. 检查提交身份及目标远程；在网页确认仓库可见性和成员权限。
4. 按 AGENTS.md，未经明确授权，不推送或更改可见性。不用强推覆盖队友工作。

现有的两个疑似误操作文件未纳入协作框架；保留原样，等待用户确认后再处理。
