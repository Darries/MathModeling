# 三人协作约定

## 责任与交接

| 可分配的人类职责（示例，不是固定岗位） | 负责内容 | 交接完成条件 |
| --- | --- | --- |
| 环境与技能维护 | 仓库、运行工具、技能审查与配置 | 队友能使用同一套工具和技能 |
| 研究方向与结果把关 | 比较 Agent 提案，确认假设，核查证据 | 关键决定经人工确认，结论有证据 |
| 图表与论文完善 | 图表美化、表达、结构、排版与修改 | 成品可读，数值与证据保持一致 |

Agent 配合 Skills 承担分析、建模提案、代码、实验、基础绘图和论文初稿。人类职责按阶段轮换、兼任或集中协作，不要求一人对应一个模块。每项任务记录执行 Agent、人工确认人和复核人；AI 自审不能代替人工批准。这里描述目标方式，不代表自动化能力已经实现。

## 一次任务如何流转

1. 在 STATUS.md 记录目标、负责人、输入材料和共享许可。
2. Agent 提出方案并填写 MODEL_HANDOFF.md，团队确认研究方向和假设，不确定内容明确标记。
3. Agent 依据已确认模型编程、运行实验，填写 EXPERIMENT_HANDOFF.md；指定成员核查结果。需改变已确认假设时，先申请变更。
4. Agent 根据已核验材料生成图表和论文初稿，填写 PAPER_HANDOFF.md；成员按需要美化图表、修改表达、核实引用。
5. 分配独立复核任务，团队确认交付。模型和参数变化后，重新运行受影响实验，更新图表与论文。

## Git 同步

保存文件只影响自己的电脑。提交记录本地版本；推送后 GitHub 才有更新；队友拉取后才会获得更新。聊天记录不会通过 Git 自动共享，关键决定必须写入文件。

建议按任务建立分支，通过 Pull Request 合并。下面以一次建模任务为例，执行前先处理已有未提交改动：

```powershell
git status
git switch main
git pull --ff-only origin main
git switch -c model/task-001
```

完成任务后，逐个选择文件，检查差异，再提交：

```powershell
git add -- 00_Collaboration/MODEL_HANDOFF.md
git diff --cached
git commit -m "Document model assumptions and equations"
```

上面命令仅演示操作：模板填入真实资料后，必须先获准共享。用户明确授权上传后，才执行 `git push -u origin model/task-001`，并在 GitHub 发起 Pull Request。由其他负责人核对后合并。

队友获取已合并的内容时，在干净的工作区运行 `git switch main` 和 `git pull --ff-only origin main`。发生冲突或快进失败时，先保留当前修改、检查原因；不要强推或丢弃文件。

## 新队友接入检查

- 已获仓库访问权限，克隆成功，Codex 工作目录正确。
- 已阅读 AGENTS.md、START_HERE.md 和当前 STATUS.md。
- 已获取允许共享的数据；只有仓库地址并不代表能够访问本机数据。
- 按实验说明运行一次，并核对预期输出；尚无实验时明确记录“未运行”。
- 不共享账号、密码或个人密钥。运行环境、第三方连接和个人技能需各自配置。
