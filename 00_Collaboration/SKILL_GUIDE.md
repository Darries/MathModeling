# 团队技能接入指南

Skill 是给 Agent 的工作说明，可以附带程序和模板。先把用途讲清楚，再引入复杂工具。

## 当前共享技能清单

目前 `.agents/skills/` 只有目录占位文件，没有已启用的团队技能。个人安装的技能和插件不自动随仓库共享。

| 能力方向 | 当前状态 | 后续验收方式 |
| --- | --- | --- |
| 任务协调与交接 | 待建设 | 能识别下一步和等待人工确认的情况 |
| 题目分析与模型提案 | 待建设 | 说明假设、备选方案和证据，等待方向确认 |
| 编程与实验 | 待建设 | 实际运行，可复现，保留失败日志 |
| 数据绘图 | 待建设 | 图表来自真实计算或明确标注的合成示例 |
| 论文初稿与排版 | 待建设 | 论断能追溯到结果，编译和版面检查通过 |
| 独立复核 | 待建设 | 能发现给定的矛盾或证据缺失，不自批通过 |

这是能力清单，不是成员分工。先完成一个小技能的审查和试用，再逐步扩大。

## 从发现到启用

1. 在 [候选目录](../08_Skill_Candidates/README.md) 登记来源，不运行下载的脚本。
2. 阅读说明和全部相关脚本，检查许可证、固定版本、依赖、安装操作、联网与文件访问。不能确定的内容写“待核查”。
3. 通过审查后，在隔离的试用文件夹中运行小任务。先用无敏感内容的样例，记录命令、输出和失败情况。
4. 通过实际验证后，放进 `.agents/skills/技能名称/`；在本文件增加来源版本、依赖、验证记录链接和维护联系人。
5. 经授权上传后，队友拉取并检查自己的依赖。更新来源版本时重新审查和测试。

没有明确许可证的外部资源暂不复制到共享仓库；审查未完成的技能不进入自动发现目录。代码或技能的安全审查通过不代表数学结论正确。

## 统一编写规范

技能文件夹与名称使用小写英文和连字符。入口 `SKILL.md` 示例：

```markdown
---
name: example-skill
description: 说明具体任务及何时使用，避免把所有工作都包含进来。
---

## 输入
列出所需文件、版本和人工确认；缺少输入时说明阻碍。

## 执行与输出
列出关键步骤、允许写入的位置、输出文件和交接方式。

## 验证
说明如何检查实际结果；未运行就记录未运行。

## 人工确认
列出必须停下确认的决定，不自行更改已确认假设。

## 依赖与参考
给出必要工具、辅助脚本和参考文件的位置。
```

此示例仅说明格式，不是已安装技能。详细资料按需放在 `references/`，可执行辅助程序放在 `scripts/`，成品模板放在 `assets/`。不需要的目录不创建。

共同的隐私、授权和数学假设规则以根目录 AGENTS.md 为准。每个技能只补充自己需要的操作细节。技能不能自行批准结果、上传资料或绕过外部代码审查。
