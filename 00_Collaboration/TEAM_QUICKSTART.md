# 三个人如何一起使用这个仓库

现阶段先搭好共同工作的地方，再逐步加入好用的技能。暂不要求每个人理解自动化系统。

## 三样东西

- GitHub：共同保存文件和历史版本的地方。
- 每个人的电脑：下载一份项目，在这里实际处理文件。
- Codex：帮助各自阅读资料、编程、画图和写作的助手。

保存文件不会自动上传。完成一项工作后，审查并提交、推送；其他人拉取更新后才会获得修改。各自的聊天记录不会随仓库同步，重要结论请写入交接文件。

## 文件放哪里

| 内容 | 位置 |
| --- | --- |
| 题目 | 01_Problem |
| 文献、参考资料 | 02_References |
| 原始数据与处理数据 | 03_Data |
| 模型程序、生成图表的程序 | 04_Code |
| 实验结果、导出的图表 | 05_Results |
| 论文源文件、最终文档 | 06_Paper |
| 讨论记录 | 07_Notes |
| 分工与交接 | 00_Collaboration |
| 已经审查、可供 Codex 使用的共享技能 | .agents/skills |
| 找到但尚未审查的技能线索 | 08_Skill_Candidates |

题目、资料、数据、结果、论文和笔记目前默认被 Git 忽略。放进本地文件夹不代表上传成功。要共享时告诉 Codex 具体允许上传哪些文件，经检查后再逐项加入；不要一次放开所有目录。

## 添加一个技能

Skill 可以理解为给 AI 的操作说明书，有时还带程序或模板。它不是一安装就保证正确的专业软件。

1. 找到有用的技能，先把链接、用途和来源版本登记在 08_Skill_Candidates，不直接运行它的脚本。
2. 检查来源、许可证、依赖、说明和脚本行为。没有审查通过的资源不放入自动发现的技能目录。
3. 审查通过后，把技能放入 `.agents/skills/技能名称/SKILL.md`，必要时附脚本和模板。
4. 用一个小任务验证效果，再把实际测试结果告诉队友。

每个技能至少说明：什么时候使用、需要什么输入、产生什么文件、需要哪些工具、如何检查结果、遇到什么情况需要询问人。技能不能擅自修改已确认的数学假设。

软件和账号权限不随仓库自动安装。队友下载技能后，仍需检查自己电脑上的依赖是否齐全。

## 作图怎么合作

- 数据图：用实际数据和绘图程序生成，保存程序、参数和输出图。
- 流程图或模型示意图：保存可编辑的源文件及导出图片，人工核对箭头和文字。
- 插画：按需使用图像生成，但不能把生成的视觉效果当成实验数据或证据。

先用代码完成论文数据图；只有需要某款软件的特定能力时再安装。安装软件并不保证 AI 能控制它，要检查当前电脑是否有可用的控制工具、接口或脚本方式。

每张正式论文图交接时写清：表达什么、来自哪次实验、单位是什么、源文件在哪里、怎样重新生成、由谁核对。只交一张图片通常不够。

## 三人先完成什么

Agent 配合 Skills 负责建模提案、代码、实验、基础图表和论文初稿。人类围绕系统安排工作：例如前期有人维护仓库和技能，中期有人组织试跑、确认方向并核查结果，后期有人集中完善图表和论文。这些任务可兼任和轮换，不是三个固定岗位。

先共同搭好工具和技能框架，再用小任务检验。每项任务指定人工确认人；方向、假设和最终成果由人确认。重要决定与实际结果写入文件，供不同成员及 Agent 接续。
