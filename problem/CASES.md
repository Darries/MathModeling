## 命名规则

- 案例目录：`三位编号_建包日期_短名称`。problem 和 results 下使用完全相同的名字。
- 建包日期固定，不因测试日期变化而改名；题目修订在 README 中增加版本和修订日期。
- 一次实际测试：在对应 results 目录下创建 `run-001_实际测试日期_成员代号/`。同案例的后续测试用 run-002、run-003，避免覆盖；多人同时开始时先约定编号。
- 程序与论文若产生，也使用相同案例目录名分别放到 code 和 paper。
- 结果目录目前只放说明和空白记录模板，不创建虚假的已运行记录。

例如 001 案例在 2026-11-24 由 A 第一次测试，记录位置为 `results/001_2026-11-23_assignment/run-001_2026-11-24_A/REPORT.md`。这是命名示例，不表示已经测试。
