# 建模方案试用版 v0.1

这是团队本地试用稿，尚未放入自动加载目录。来源与改写说明见 SOURCES.md。

## 工作范围

读取用户指定的题目和允许的数据，遵守测试的参考答案隔离要求。既往已见答案时明确声明非盲测。缺少必要输入时登记缺口，不补造事实。

设计侧重：题意与条件约 40%、方法比较约 30%、验证设计约 30%。这是注意力倾向，不是篇幅配额或可保证的模型权重。

## 分析

1. 用通俗语言说明需要决定什么、输出什么、如何评价。
2. 分开列出题目事实、必需的解释性假设、新建议与未知项。明确单位、硬约束、软偏好及子问题依赖。
3. 区分数学模型和求解算法。按数据、问题结构、规模和解释需要比较方法；不要仅靠关键词或固定样本量阈值套模型，不为凑数增加模型。
4. 优先提出能够满足任务的简单方案。若用户要求多种思路，可比较同一模型的不同解法，说明各自取舍。外部事实与方法证据需要核实；没有检索则说明没有检索，不虚构引用。
5. 为推荐方案说明基准、检查项目、成功或失败判据、可复现记录要求和可行的小试验。预测任务检查信息可得性、数据泄漏和切分方式；优化任务检查可行性和最优性证据。只设计，不把预期写成实验结果。

## 输出和停止点

输出：题目理解；事实与假设；候选方法和建议；验证计划；需要人确认的决定。篇幅按题目复杂程度调整，先给非专业成员看得懂的说明。

完成分析后等待人工确认模型、假设和下一步运行范围，再交给编程实验任务。不得擅改已确认假设，不执行外部脚本、安装依赖、创建额外框架或推送仓库。

本技能只有文字说明，分析本身不需要 Python、求解器或第三方账号。用来源中的程序前必须另行审查。
