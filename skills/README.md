# 技能工作台

这是当前建设重点。先按用途找技能，再看它是否审查和实测通过。

| 分类 | 放什么 |
| --- | --- |
| [analysis-modeling](analysis-modeling/README.md) 分析与建模 | 题目理解、资料研究、模型提出与比较 |
| [coding-experiments](coding-experiments/README.md) 编程与实验 | 数据处理、编程、调试、实验与验证 |
| [visualization](visualization/README.md) 作图与美化 | 数据图、流程图、示意图、配色与布局 |
| [paper-layout](paper-layout/README.md) 论文与排版 | 写作、修改、引用、LaTeX 与版面检查 |

跨类别技能只登记一次，其余用途写在记录里。环境配置或协调技能按它主要服务的用途登记，不为少量工具再建一套分类。

## 每人如何贡献

1. 找到技能后，复制 [简短记录模板](TEMPLATE.md) 到对应分类，以技能名称命名。
2. 检查原始来源、固定版本、许可证、依赖和所有相关脚本，包括安装、联网和文件访问行为；未审查不执行。
3. 审查通过后，在独立小目录中实际试用，记录输入、命令、输出和问题。
4. 通过后将真实技能放在 `.agents/skills/技能名称/SKILL.md`，在分类记录里链接它。不要保存两份相同技能代码。
5. 经授权上传后，队友拉取，按记录配置自己的依赖并尝试使用。

状态使用：待审查 → 待实测 → 可用；不合适可标“暂缓”或“停用”。新版外部代码需重新审查，许可证不明确时不复制分发。

团队自编技能同样需要明确用途、输入输出、依赖和实测。组合技能要记录各项依赖，不能因组合而跳过审查。

当前四类只有目录说明，没有已启用技能。`.agents/skills` 是工具加载目录，日常统一从这里浏览。
